# V2.7 — Plano de Refatoração

## 1. Objetivo

Transformar a auditoria inicial da branch `V2.7` em um roteiro vivo, incremental e verificável para reduzir acoplamento, preservar comportamento e melhorar a manutenibilidade do frontend e do backend.

A execução seguirá:

```text
AUDITORIA → PLANO → PREPARAÇÃO DOS TESTES → PEQUENA REFATORAÇÃO → TESTES → COMMIT → PRÓXIMA REFATORAÇÃO
```

Este documento será atualizado a cada fase, mantendo decisões, riscos, resultados e bloqueios.

## 2. Contexto Atual

- Branch auditada: `V2.7`.
- Working tree na auditoria: limpo.
- `frontend-flet/app/application.py`: aproximadamente 5.371 linhas, concentrando ciclo de vida, navegação, telas, formulários, diálogos, validações, API, JWT, WebSocket, tracking, GPS e mapas.
- Backend com maiores módulos em `backend-api/app/api.py` e `backend-api/app/routers/rotas.py`, ambos com aproximadamente 1.036 linhas.
- O frontend já possui módulos auxiliares para API, configuração, dashboard, geolocalização, tracking e mapas.
